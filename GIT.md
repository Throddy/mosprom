# Работа с git

## Правила

1. Каждый коммитит только свою папку из `STRUCTURE.md`. Поэтому изменения разных участников не пересекаются.
2. Одна задача из `PLAN.md` даёт одну ветку и один PR. Ветка живёт не дольше 2–3 часов работы.
3. В `main` напрямую не пушит никто. Вливает только Максим.
4. `core/` и `CONTRACT.md` меняются отдельным PR `contract: ...` по разделу 8 контракта.
5. Зависимости добавляются только в `requirements.txt` своей зоны.
6. В `PLAN.md` каждый правит только свой раздел, в том же PR, что и задачу.

## Первый запуск

```bash
git clone <url репозитория>
cd <папка репозитория>
cp .env.example .env
```

## Цикл задачи

1. Создать ветку от свежего `main`:

```bash
git switch main
git pull
git switch -c ml/ML-3-onnx
```

Имя ветки: `<зона>/<номер задачи>-<коротко>`. Зоны: `ml`, `logic`, `backend`.

2. Закоммитить работу. Добавлять только свою папку:

```bash
git add ml/ configs/models.yaml PLAN.md
git commit -m "ml: добавлен onnx-бэкенд"
```

3. Перед PR подтянуть `main` в ветку:

```bash
git fetch origin
git merge origin/main
git push -u origin ml/ML-3-onnx
```

4. Открыть PR в `main`. Заголовок оформляется как коммит, тело по шаблону:

```
Что: бэкенд onnx, пре- и постпроцессинг yolov8n-pose
Задача: ML-3
Как проверено: create_detector("onnx") на 20 кадрах из ALL-1, боксы совпадают с ultra
```

5. После вливания удалить ветку и вернуться к шагу 1.

```bash
git switch main
git pull
git branch -d ml/ML-3-onnx
```

## Конфликт

Конфликт возникает только в общих файлах. Его решает автор PR в своей ветке:

```bash
git fetch origin
git merge origin/main
# поправить файлы с пометками <<<<<<< и >>>>>>>
git add <файлы>
git commit
git push
```

Если конфликт в чужой зоне, ничего не править и написать владельцу зоны.

## Максим: вливание

1. Проверить, что PR меняет только файлы зоны автора.
2. Запустить `python scripts/smoke.py` на ветке PR.
3. Влить через «Squash and merge». Ветка в `main` превращается в один коммит.
4. Удалить ветку.

Готовые PR вливаются не реже раза в 2 часа. За час до каждого чек-поинта Максим вливает всё готовое, после этого в `main` принимаются только исправления.

## Не коммитим

Видео, веса, программы TPU, `.env`, снимки событий. Полный список приведён в `.gitignore` из `STRUCTURE.md`. Если файл попал в коммит, его нужно убрать до PR:

```bash
git rm --cached <файл>
git commit -m "ml: удалён лишний файл"
```
