# СОКОЛ

Система Обнаружения и Контроля Опасностей на LinQ.

Веб-сервис контроля нарушений техники безопасности по видео с камер для мастеров и служб охраны труда на производстве и складе. Нейросети находят людей, их позы и технику, правила превращают нарушения в тревоги, оператор разбирает их в браузере. Модели скомпилированы под ускоритель LinQ TPU. Хакатон «Открой#Моспром», кейс LinQ, 23–25 октября 2026.

Стенд (только просмотр): https://sokol.157.22.134.21.sslip.io

## Что умеет

- `fall` — падение и неподвижность: корпус отклонён от вертикали по ключевым точкам, затем человек неподвижен.
- `danger_zone` — человек в опасной зоне: точка ног внутри полигона зоны.
- `proximity` — сближение с техникой: точка ног ближе заданного числа ростов человека к боксу техники, водитель в кабине не считается.
- `running` — бег в зоне работы техники: скорость в ростах человека в секунду, с учётом бега к камере и от неё.
- Лента тревог по WebSocket: снимок с выделенным нарушителем, камера, зона, время; решения «подтверждено», «ложное», «передано мастеру».
- Журнал событий с фильтрами по типу, камере, зоне, статусу и времени.
- Редактор зон и правил по камерам: полигон на кадре, параметры правил, расписание; изменения применяются без перезапуска.
- Аналитика: статистика тревог, точность распознавания, замеры скорости ONNX и LinQ.
- Подавление повторных тревог: разрыв трека не порождает новое событие об уже идущем нарушении.
- Размытие лиц на видео и снимках (`BLUR_FACES=1`).
- Детектор на CPU (ONNX Runtime) или на LinQ TPU (`DETECTOR_BACKEND=linq`).

Расстояние и скорость нормируются на рост человека в кадре, калибровка камеры не нужна. Параметры правил: `backend/README.md`, раздел «Правила».

## Как работает

```
камера (файл, RTSP, HLS, папка кадров)
  -> backend: поток чтения на камеру, последний кадр
  -> ml: детектор yolov8n-pose + yolov8n (ONNX Runtime на CPU или LinQ TPU)
  -> logic: трекер ByteTrack -> правила-плагины -> событие
  -> backend: SQLite, снимок нарушителя, WebSocket /ws/events, видео /stream и HLS
  -> frontend: лента тревог, журнал, камеры и зоны, аналитика
```

- Детектор берёт последний кадр каждой камеры: при перегрузке падает частота обработки, а задержка не накапливается.
- Камера закреплена за одним обработчиком детектора, поэтому её кадры идут по порядку и трекер не путается.
- Событие создаётся, только если нарушение длится не меньше `min_duration`: это защита от ложных тревог на одном кадре.
- Одно нарушение одного человека даёт одно событие; повтор рядом в течение 10 с подавляется.
- Правило — отдельный модуль в `logic/rules/`: новое правило появляется в интерфейсе без правки фронтенда.

Модули общаются через типы и API из `CONTRACT.md`.

## LinQ TPU

Подробно: `ml/README.md`.

- **Путь модели.** ONNX (экспорт ultralytics) → SDK LinQ `tpu_framework`: квантование int8 по 250 калибровочным кадрам и компиляция под `TPU_H1M` → программа `.tpu`. Граф разрезан: свёрточная часть обеих моделей идёт на TPU в int8, декодирование боксов, сборка выхода и NMS — на CPU. При квантовании полного графа обнулялись уверенности ключевых точек.
- **Запуск.** Программы `.tpu` лежат в `/auto/cache/<LINQ_LOGIN>/` на сервере Jupyter рядом с TPU. Там же работает ретранслятор `python -m ml.relay` (`notebooks/relay.md`). Бэкенд отправляет JPEG до 640 px через VPN и RabbitMQ, ретранслятор вызывает TPU. Включение: `DETECTOR_BACKEND=linq` и переменные `LINQ_*` в `.env` (`ml/README.md`, раздел «Переменные окружения»).
- **Сверка с ONNX** на 20 кадрах: средний IoU боксов 0.950, минимальный 0.892 через ретранслятор; 0.953 / 0.909 при прямом вызове TPU.
- **Замеры** (`reports/benchmarks.json`):

| Замер | Кадров/с | Время на кадр |
|---|---|---|
| LinQ TPU, только время ускорителя, pose и det | 10.98 | 91.1 мс |
| LinQ через сервис стенда, ретранслятор 8 процессов, 8 потоков | 0.80 | задержка одного кадра 5–10 с |
| ONNX Runtime, CPU Apple M4, 1 поток | 8.45 | 118.4 мс |

- **Почему живые тревоги на стенде идут на ONNX.** Очередь облачного сервиса LinQ общая для всех команд, кадр идёт 5–10 с. На объекте с собственной платой этого пути нет: по времени ускорителя одна плата обрабатывает `floor(10.98 / частота)` камер — 5, 3, 2 и 1 камеру при 2, 3, 5 и 10 кадрах/с. Сеть и очередь в этот расчёт не входят.

## Быстрый запуск

Репозиторий приватный, доступ выдаёт владелец. Модели ONNX (`ml/weights/`), сборка интерфейса (`frontend/dist/`) и видео демо (`data/videos/demo/`) уже в клоне. Интернет нужен для `git clone` и установки зависимостей Python при первом запуске (около 5 минут).

### macOS и Linux (Ubuntu 22.04)

Нужны Python 3.10 и Git. На Ubuntu также: `sudo apt-get install -y python3.10 python3.10-venv libgl1 libglib2.0-0`. Если на macOS нет `python3.10`: `uv python install 3.10`, затем `PYTHON="$(uv python find 3.10)" bash scripts/start_demo.sh` (`ml/README.md`, раздел «Установка»).

```bash
git clone https://github.com/Throddy/mosprom.git
cd mosprom
bash scripts/start_demo.sh
```

`scripts/start_demo.sh` проверяет комплект (`scripts/check_distribution.py`), создаёт `.venv` в клоне (`python3.10 -m venv .venv`), ставит зависимости (на Linux x86_64 — PyTorch без CUDA, `deploy/torch-cpu.txt`) и запускает сервер. `.env` не читается. Адрес: `http://127.0.0.1:8000`. Остановка: `Ctrl+C`. Другой порт: `bash scripts/start_demo.sh --port 8010`.

### Windows 10/11 (PowerShell)

Проверяется на Windows. Нужны Python 3.10 (установщик с python.org, команда `py -3.10`) и Git. Команды из корня клона повторяют `scripts/start_demo.sh`:

```powershell
git clone https://github.com/Throddy/mosprom.git
cd mosprom
py -3.10 -m venv .venv
Set-ExecutionPolicy -Scope Process Bypass
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python scripts\check_distribution.py --cameras deploy/cameras.local-demo.yaml
New-Item -ItemType Directory -Force backend\data\demo | Out-Null
if (-not (Test-Path backend\data\demo\cameras.yaml)) { Copy-Item deploy\cameras.local-demo.yaml backend\data\demo\cameras.yaml }
Get-ChildItem Env:LINQ_* -ErrorAction SilentlyContinue | Remove-Item
$env:PIPELINE="1"; $env:DETECTOR_BACKEND="onnx"; $env:DETECTOR_WORKERS="1"; $env:TILED_CAMERAS=""; $env:TILED_WORKERS="1"
$env:CAMERAS_PATH="backend/data/demo/cameras.yaml"; $env:DB_PATH="backend/data/demo/events.sqlite3"
$env:BACKEND_HOST="127.0.0.1"; $env:BACKEND_PORT="8000"; $env:READ_ONLY="0"; $env:BLUR_FACES="0"
$env:MAX_STREAMS="30"; $env:STREAM_FPS="15"; $env:SOURCE_LOOP="1"; $env:REMOTE_HOSTS=""; $env:LOG_LEVEL="INFO"
python -m backend
```

Адрес: `http://127.0.0.1:8000`. Остановка: `Ctrl+C`. Сборка фронтенда нужна только после изменения `frontend/src/`: `npm.cmd --prefix frontend ci`, затем `npm.cmd --prefix frontend run build`.

### Что будет на экране

Через 10–30 с после запуска в ленте появляются тревоги двух камер на видео из `data/videos/demo/`: `demo_reel` — ролик со сценами без нарушений, падением, сближением с погрузчиком и бегом; `demo_zone` — заход в зону у двери (`deploy/cameras.local-demo.yaml`). Без детектора, на тестовых событиях: `PIPELINE=0 .venv/bin/python -m backend`.

## Результаты

Точность на контрольном наборе `data/videos/test/` — видео, не участвовавшие в подборе порогов (`reports/metrics.json`, детектор `onnx`):

| Правило | Найдено | Ложных | Пропущено | Точность | Полнота |
|---|---|---|---|---|---|
| `fall` | 1 | 0 | 0 | 1.0 | 1.0 |
| `danger_zone` | 1 | 0 | 0 | 1.0 | 1.0 |
| `proximity` | 3 | 1 | 0 | 0.75 | 1.0 |
| `running` | 1 | 1 | 4 | 0.5 | 0.2 |

На сцене без нарушений `normal_walking.MOV` — 0 тревог.

Задержка тревоги от начала нарушения (`ml/README.md`, «Метрики»): `fall` 3.3 с, из них 1.5 с — ожидание неподвижности; `danger_zone` 1.6 с; `proximity` 2.5–6.3 с; `running` 1.3 с на `running_07.mov`. Задержка в основном состоит из ожидания правила, заданного против ложных тревог.

Производительность CPU (`backend/README.md`, «Производительность»): Apple M4 Pro, детектор `onnx`, 2 камеры по 10 кадров/с, от кадра до `event_new` p50 69.7 мс, p95 90.9 мс.

## Ограничения

- Живые тревоги на LinQ через облачный сервис не успевают за видео: 0.80 кадра/с и 5–10 с на кадр.
- Бег прямо на камеру без калибровки не отличается от шага рядом с камерой; бег со смазанным силуэтом не находится.
- `proximity` срабатывает и рядом с припаркованной техникой: движение техники не учитывается.
- На общих планах люди мелкие: для трансляций включаются плитки, они в 3–4 раза дороже по времени кадра.
- Модели не дообучались, погрузчик детектируется классом COCO `truck`; на одной трансляции деревянные щиты принимаются за технику.
- Метрики посчитаны на небольшом контрольном наборе: по одному видео на `fall` и `danger_zone`.
- API без авторизации (`CONTRACT.md`, раздел 6), сервер по умолчанию слушает только `127.0.0.1`.

Полный список: `backend/README.md`, «Известные ограничения»; `ml/README.md`, «Ограничения».
