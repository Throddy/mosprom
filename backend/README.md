## Запуск

Установка и локальное демо одной командой: `README.md`, раздел «Быстрый запуск». Запуск с собственным `.env` из корня репозитория (сервер сам `.env` не читает):

```bash
cp .env.example .env
set -a; source .env; set +a
.venv/bin/python -m backend
```

- Адрес `http://127.0.0.1:8000`. Камеры `cam1` и `cam2` из `configs/cameras.yaml` читают `data/demo.mp4` по кругу, первое падение — примерно через 8 с. Без детектора: `PIPELINE=0 .venv/bin/python -m backend`, 40 тестовых событий из `backend/fixtures.py` и новая тревога раз в `FIXTURE_WS_INTERVAL` с.
- Модели `ml/weights/*.onnx` и сборка `frontend/dist/` хранятся в git. После изменения `frontend/src/` сборка пересобирается и коммитится: `npm --prefix frontend ci`, `npm --prefix frontend run build`. На Linux x86_64 PyTorch без CUDA: `bash deploy/python_deps.sh .venv/bin/python`.

## Переменные окружения

Все переменные, которые читает код, есть в `.env.example`.

| Переменная | По умолчанию | Значение |
|---|---|---|
| `DETECTOR_BACKEND` | `onnx` | бэкенд детектора: `onnx` или `linq` |
| `DETECTOR_WORKERS` | `1` | число обычных обработчиков, у каждого свой детектор; раздел «Производительность» |
| `TILED_CAMERAS` | пусто | точные `id` камер через запятую, которые обрабатываются детектором с плитками; раздел «Производительность» |
| `TILED_WORKERS` | `1` | число обработчиков с плитками для камер из `TILED_CAMERAS` |
| `ORT_THREADS` | `0` | потоков на сессию ONNX Runtime (`intra_op`, `inter_op` 1, последовательный режим); `0` — по умолчанию ORT, столько, сколько ядер. `backend/threads.py` подменяет `onnxruntime.InferenceSession` до создания детекторов |
| `TORCH_THREADS` | `0` | потоков PyTorch (`torch.set_num_threads`, interop 1); ultralytics сам сбрасывает число, подменённая функция всегда ставит это значение |
| `CV2_THREADS` | `0` | потоков OpenCV (`cv2.setNumThreads`); на macOS OpenCV собран с GCD и значение не действует |
| `STREAM_WIDTH` | `0` | ширина кадра `/stream` с сохранением пропорций, до рисования разметки; `0` — исходная. Снимки событий и `/frame` в исходном размере |
| `STREAM_QUALITY` | `85` | качество JPEG кадров `/stream` |
| `STREAM_DELAY` | `auto` | задержка показа, с, или `auto`; раздел «Показ видео» |
| `STREAM_BUFFER_MAX` | `12` | предел задержки показа и буфера кадров показа, с |
| `EVENTS_KEEP_MINUTES` | `0` | больше 0: раз в 60 с удаляются закрытые события с `ts_confirm` старше `now − EVENTS_KEEP_MINUTES` минут и их снимки в `backend/media/`; открытые остаются. В лог число удалённых не чаще раза в 5 минут |
| `ADMIN_LOCAL` | `0` | при `READ_ONLY=1` и `ADMIN_LOCAL=1` `PUT /api/cameras/{id}` и `PATCH /api/events/{id}` разрешены запросам с `127.0.0.1` или `::1` без заголовков `X-Forwarded-For`, `X-Real-IP`, `Forwarded` (SSH-туннель; через Caddy заголовок есть всегда). Если есть заголовок `Origin`, он должен быть `http://127.0.0.1:8000` или `http://localhost:8000`, иначе 403: чужой сайт в браузере администратора не может записать через туннель. В лог: метод, путь, `admin local` |
| `CAMERAS_BASE` | `configs/cameras.yaml` | базовый файл камер: читается, если файла правок `CAMERAS_PATH` ещё нет; `PUT` пишет в `CAMERAS_PATH`, базовый файл не меняется |
| `HLS_ENABLED` | `0` | `1`: видео камер в H.264 (HLS) по `/hls/<camera_id>/index.m3u8`, раздел «Показ видео» |
| `HLS_DIR` | `backend/data/hls` | папка сегментов HLS, путь от корня репозитория |
| `HLS_BITRATE` | `1800k` | битрейт H.264 на камеру; `maxrate` ×1.3, `bufsize` ×2 |
| `READ_ONLY` | `0` | `1`: `PUT /api/cameras/{id}` и `PATCH /api/events/{id}` возвращают 403 `{"detail": "Демо-стенд: только просмотр"}`, кроме `ADMIN_LOCAL` |
| `BLUR_FACES` | `0` | `1`: голова каждого человека пикселизируется на `/stream`, `/frame`, HLS и снимках событий: квадрат по точкам носа, глаз и ушей, без точек — верхние 22 % бокса |

| `STREAM_FPS` | `15` | частота кадров показа; камера читается с частотой `max(fps, STREAM_FPS)`, детектор получает не больше `fps` кадров/с камеры |
| `REMOTE_HOSTS` | пусто | хосты, разрешённые в `source` с `http(s)://` и `rtsp://`: точное имя или поддомен; пусто — удалённые источники не принимаются, адрес с логином и паролем тоже |
| `PIPELINE` | `1` | `1`: реальные события, камеры обрабатываются детектором и правилами, события в базе `DB_PATH`; `0`: тестовые события в базе в памяти, тестовая тревога раз в `FIXTURE_WS_INTERVAL` с |

| `DB_PATH` | `backend/data/events.sqlite3` | база событий при `PIPELINE=1`, путь от корня репозитория |
| `CAMERAS_PATH` | `configs/cameras.local.yaml` | файл правок камер из интерфейса; если его нет, камеры берутся из `CAMERAS_BASE` |
| `SOURCE_LOOP` | `1` | `0`: видеофайл и папка кадров не начинаются сначала после конца |
| `BACKEND_HOST` | `127.0.0.1` | адрес сервера |
| `BACKEND_PORT` | `8000` | порт сервера |
| `LOG_LEVEL` | `INFO` | уровень логов в консоли: `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `LINQ_LOGIN`, `LINQ_AMQP_HOST`, `LINQ_AMQP_PORT`, `LINQ_AMQP_USER`, `LINQ_AMQP_PASSWORD` | нет | только для `DETECTOR_BACKEND=linq`, описание в `ml/README.md` |

## API

Пути, параметры и форматы JSON описаны в `CONTRACT.md`, раздел 6. Ошибки возвращаются HTTP-кодом и телом `{"detail": "текст"}`, ошибки валидации запроса — кодом 422.

- `GET /api/events`: `limit` от 1 до 500 (по умолчанию 50), `offset` не меньше 0; `PATCH /api/events/{id}`: `comment` не длиннее 1000 символов; `PUT /api/cameras/{id}`: проверки в разделе «Камеры».
- Если есть `frontend/dist/index.html`, сборка фронтенда раздаётся по `/`. Снимки событий сохраняются в `backend/media/` и раздаются по `/media/...`. `GET /api/cameras/{id}/frame?w=480`: кадр шириной `w` (160–1920) с сохранением пропорций, JPEG 70, для превью; без `w` — как раньше. При `HLS_ENABLED=1` видео камер в H.264 раздаётся статикой по `/hls/<camera_id>/index.m3u8` из `HLS_DIR` (раздел «Показ видео»).

## Камеры

Базовый файл `CAMERAS_BASE` (по умолчанию `configs/cameras.yaml`, в git) и файл правок `CAMERAS_PATH` (по умолчанию `configs/cameras.local.yaml`, в git не попадает по `configs/*.local.yaml`). При старте читается файл правок, если он есть, иначе базовый (на стенде `configs/cameras.demo.yaml` и `configs/cameras.demo.local.yaml`). `PUT` проверяет камеру, атомарно записывает все камеры в файл правок и применяет изменения без перезапуска. Сброс к базовым камерам: удалить файл правок и перезапустить сервер.

Проверки `PUT`. Ошибка даёт код 422 и `{"detail": "<ошибки через '; '>"}`:

| Поле | Правило |
|---|---|
| `id`, `name` | непустые строки, `name` до 100 символов |
| `fps` | число, `0 < fps <= 30` |
| `source` | `rtsp://`, `http://` или `https://` с хостом из `REMOTE_HOSTS` (точное имя или поддомен), либо относительный путь внутри `data/` без `..`, файл или папка существует |
| `zones` | не больше 20 зон; `id` — непустые уникальные строки, `name` — строка до 100 символов, `polygon` от 3 до 50 точек, координаты — конечные числа от 0 до 1 |
| `rules` | не больше 20 правил |
| `rules[].type` | строка, правило есть в реестре (`GET /api/rules`) |
| `rules[].zone` | `null` или строка; у правила с `needs_zone` зона задана и есть в `zones`; заданная зона у других правил тоже должна быть в `zones` |
| `rules[].schedule` | `null` или две строки `HH:MM`, часы 0–23, минуты 0–59 |
| `rules[].params` | объект; только параметры из описания правила, значения — конечные числа от 0 до 1000 |

Значение не того типа даёт 422, а не 500. `PUT` выполняется под одной блокировкой: одновременные запросы не теряют изменений.

```bash
python scripts/check_cameras.py
```

## Пайплайн

| Вид | Значение `source` | Чтение |
|---|---|---|
| Файл | путь к видео от корня репозитория | в темпе реального времени, лишние кадры пропускаются |
| RTSP | `rtsp://...` | отдельный поток хранит последний кадр, переподключение каждые 2 с |
| Папка | путь к папке с `*.jpg`, `*.jpeg`, `*.png` | файлы по имени |
| HTTP(S), HLS, YouTube, Ivideon | раздел «Демо-стенд» | отдельный поток, переподключение каждые 5 с |

- На каждую камеру отдельный поток чтения. Детектор работает в `DETECTOR_WORKERS` обработчиках (и `TILED_WORKERS` для камер с плитками), камера закреплена за одним обработчиком, обработчик берёт последний кадр своих камер: отставание не накапливается. Если источник не открылся или закончился, камера получает `online: false`, повторное открытие через 5 с.

```bash
python scripts/check_pipeline.py
```

## События

- События сохраняются в SQLite (`DB_PATH`, папка `backend/data/` в git не попадает). Снимок: кадр с нарушителем в красной рамке, `backend/media/<camera_id>/<id>.jpg`, адрес `/media/<camera_id>/<id>.jpg`.
- Новое событие уходит в `/ws/events` как `event_new`, закрытие и смена статуса — как `event_update`. При старте с `PIPELINE=1` события, открытые на момент остановки, закрываются: `ts_end = ts_confirm`.
- Повторы (`logic/engine.py`): новое событие не создаётся, если на той же камере есть событие того же типа и той же зоны, открытое или закрытое не более `REPEAT_WINDOW = 10` с назад, и точка ног нового трека ближе `REPEAT_DIST = 1.0` высоты бокса к последней позиции того нарушения. Открытое событие пропавшего трека продолжается новым треком без `event_new`; закрытое заново не открывается, новое только подавляется. Продолжение и подавление действуют не дольше `REPEAT_MAX = 60` с от `ts_confirm`. Счётчик: `Engine.suppressed_counts`. `EVENTS_KEEP_MINUTES` удаляет старые закрытые события и их снимки.

```bash
python scripts/check_events.py
```

## Скрипты

### `run_offline.py`

Прогон видео через детектор и правила без сервера, раздел 7 `CONTRACT.md`. Используется для метрик ML-7.

```bash
python scripts/run_offline.py --video PATH --camera ID --out PATH [--fps F] [--use-schedule]
```

| Аргумент | Значение |
|---|---|
| `--video` | видео `.mp4` или `.mov` |
| `--camera` | камера из `configs/cameras.yaml`: зоны и правила |
| `--out` | файл JSONL: одна строка на `Event` (`dataclasses.asdict`), по возрастанию `ts_confirm` |
| `--fps` | частота обработки, по умолчанию `fps` камеры |
| `--use-schedule` | учитывать `schedule` правил по текущему времени. Без флага расписание отключено, чтобы результат не зависел от времени запуска |

- `ts_*` в выводе — секунды от начала видео; события, открытые на последнем кадре, закрываются с `ts_end` последнего кадра. Детектор — `DETECTOR_BACKEND`.
- Итоговая строка в stdout: `<video>: <кадров> frames, <событий> events, <тип>=<число> ..., <секунд> s`. Нет камеры или видео не открывается — код возврата 2.

## Правила

Движок `logic/engine.py` на каждый кадр обновляет треки (`supervision.ByteTrack`), вызывает правила камеры и превращает нарушения в события (`CONTRACT.md`, раздел 5). Кандидат удаляется, если нарушения нет дольше `GRACE` 1.0 с; событие закрывается, если нарушения или трека нет дольше `CLOSE_AFTER` 2.0 с. Правило с ошибкой в настройках (например, неверное `schedule`) пропускается с одним предупреждением в логе, остальные работают.

Как добавить правило: модуль в `logic/rules/` (имя без `_` в начале) с подклассом `Rule` из `logic/rules/base.py` — поля `type`, `title`, `severity`, `needs_zone`, `params` (обязателен `min_duration`) и метод `check(ctx, cfg)`, который возвращает `{track_id: extra}` нарушителей кадра. Модуль подхватывается автоматически и появляется в `GET /api/rules`.

| `type` | Что проверяет | Параметры по умолчанию |
|---|---|---|
| `danger_zone` | точка ног человека (середина нижней грани бокса) внутри полигона зоны | `min_duration` 1.0 с |
| `fall` | корпус отклонён от вертикали (по плечам и бёдрам, без точек по пропорции бокса) и человек неподвижен | `min_duration` 1.5 с, `angle` 60.0 град, `aspect` 1.2, `still_window` 1.5 с, `still_tol` 0.3 длины тела |
| `proximity` | расстояние от точки ног до бокса техники (`car`, `truck`, `bus`, `forklift`), делённое на рост человека, меньше `dist`. Водитель (точка ног внутри бокса техники, не меньше `inside_ratio` площади бокса человека внутри, точка ног выше нижнего края техники не меньше чем на `cab_min` её высоты) для своей техники не учитывается | `dist` 2.0 роста человека, `inside_ratio` 0.7, `cab_min` 0.15 высоты техники, `min_duration` 0.5 с |
| `running` | скорость за окно `window` больше `speed`: `v = sqrt(v_lat^2 + v_depth^2)`. `v_lat` — смещение точки ног, делённое на рост и время. `v_depth` — бег к камере или от неё: `r_h = ln(h_last / h_first)`, `r_w = ln(w_last / w_first)`; при разных знаках 0, иначе `depth_k * min(abs(r_h), abs(r_w)) / dt`; только если человек стоит прямо во всех записях окна (угол корпуса меньше `upright_angle`, без точек высота/ширина бокса больше `upright_aspect`) | `speed` 1.5 роста человека/с, `window` 1.0 с, `depth_k` 5.0, `upright_angle` 30.0 град, `upright_aspect` 1.5, `min_duration` 1.0 с |

Расстояние и скорость нормируются на высоту бокса человека, калибровка камеры не нужна. Если у `proximity` или `running` задана `zone`, учитываются только люди с точкой ног в этой зоне.

```bash
python scripts/check_logic.py
python scripts/check_rules.py
```

### Подбор порогов

Пороги подбираются только на `data/videos/dev/` (камеры `test_*`), контрольный набор `data/videos/test/` — только для метрик ML-7 (`ml/README.md`, «Метрики»). Условия для любых порогов: 0 ложных тревог на всех видео набора и на `data/demo.mp4` для `cam1` и `cam2`, все проверки `check_rules.py` проходят. Итог подбора (BE-11…BE-11f):

| Правило | Итог |
|---|---|
| `fall` | `min_duration` 3.0 → 1.5 с, `still_window` 2.0 → 1.5 с; задержка тревоги на `fall.mov` 5.5 → 3.5 с |
| `danger_zone` | без изменений, задержка 0.9 с |
| `running` | компонента по глубине `depth_k` 5.0 только при прямой стойке, `speed` 1.5, глубина по высоте и ширине бокса (вставание не даёт тревоги); бег на `running.mov` находится, задержка 4.3 с, бег к камере `running_02.mov` — нет |
| `proximity` | водитель в кабине не считается (`inside_ratio` 0.7, `cab_min` 0.15), `dist` 1.0 → 2.0: пешеход у вил на `proximity.mp4` находится |

Итог `python scripts/eval_offline.py` на dev после BE-11f: `tp` по одному на `danger_zone.mov`, `fall.mov`, `running.mov`, `proximity.mp4`; `fn` 1 на `running_02.mov`; 0 ложных тревог на 118.6 с видео. Частота шагов по лодыжкам (BE-11g) проверена и не принята: при беге к камере и при 10 кадрах/с шаги на кадре не разрешаются.

```bash
python scripts/eval_offline.py --trace running
python scripts/eval_offline.py --only proximity.mp4 --trace proximity
```
`--trace running` печатает покадрово `ts`, `track_id`, точку ног, высоту бокса, скорость `v` и отношение высот бокса за окно; `--trace proximity` — людей, технику и минимальное `d_norm` на камере `test_proximity`; `--only VIDEO` оценивает одно видео.

### Обработчики и плитки

- `DETECTOR_WORKERS` — число обработчиков, у каждого свой детектор; камеры распределяются по кругу, камера закреплена за одним обработчиком. На Mac при 6 камерах: 19.8 кадра/с суммарно при 1 обработчике, 16.5 при 2, 11.85 при 4; с `ORT_THREADS=4` и 2 обработчиками — 23.55. На сервере подбирается заново: `deploy/README.md`, «Подбор на сервере».
- `TILED_CAMERAS` — точные `id` камер для детектора с плитками (`create_detector(<DETECTOR_BACKEND>, tiles=True)`), их обрабатывают `TILED_WORKERS` отдельных обработчиков. Если бэкенд плитки не поддерживает, камеры переходят к обычным обработчикам с одним предупреждением в логе.
- Mac M4 Pro, `deploy/env.demo`, 4 трансляции с плитками: `live_*` около 0.56 кадра/с при заданных 2, задержка около 2 с, `demo_reel` 4.4 кадра/с при заданных 10. Без плиток, с чтением HLS через `ffmpeg -re`: `live_*` около 2.0 кадра/с.

Удалённые источники `source`:

## Показ видео

`/stream`, `/frame` и HLS показывают кадр с задержкой `D`; рамки, точки, подписи и размытие считаются для этого же кадра. Тревоги и их `ts` от показа не зависят.

- Камера хранит кадры показа (не чаще `STREAM_FPS`) за последние `D + 1` с, не больше `STREAM_BUFFER_MAX`, и последние 30 результатов детектора по `ts` обработанного кадра.
- `D` = p90 задержки обработки за 20 кадров + `1 / fps` камеры + 0.2 с, не больше `STREAM_BUFFER_MAX` (`STREAM_DELAY=auto`) или число из `STREAM_DELAY`. `D` видно в подписи кадра: `delay … s`.
- Трек из двух результатов вокруг кадра: бокс и точки линейно интерполируются по времени. Трек из одного результата рисуется, если тот не дальше `1 / fps`; без результатов рядом — кадр без рамок.
- Размытие (`BLUR_FACES=1`): по интерполированным трекам и людям из детекций результатов в пределах `2 / fps`, в том числе без подтверждённого трека. Если у камеры из `TILED_CAMERAS` или `live_*` нет результатов в этом окне, размываются верхние 40 % кадра.
- MJPEG: один JPEG на кадр показа для всех зрителей (`STREAM_WIDTH`, `STREAM_QUALITY`). `/frame` — тот же кадр с размытием, без разметки; `/frame?w=480` — превью для «Монитора».

### HLS (`HLS_ENABLED=1`)

- На камеру один поток раз в `1 / STREAM_FPS` пишет тот же кадр показа, что идёт в MJPEG, в `ffmpeg` (`backend/hls.py`): `libx264`, `veryfast`, GOP `2 × STREAM_FPS`, `HLS_BITRATE`, сегменты по 2 с, в плейлисте 6. Запись не зависит от числа зрителей.
- `/hls/<camera_id>/index.m3u8` и `seg_*.ts` — статика: плейлист `Cache-Control: no-cache`, сегменты `max-age=60`. На стенде их отдаёт Caddy (`deploy/Caddyfile`).
- Фронтенд (`frontend/src/components/LiveVideo.tsx`) играет HLS в `<video>` (Safari сам, остальные через `hls.js`); без плейлиста, при ошибке или 15 с без воспроизведения — MJPEG `/stream`. На «Мониторе» вместо потоков превью `/frame?w=480` раз в 2 с.
- Mac, 1280 px, 15 кадров/с, `1800k`: 50 зрителей HLS — 2.2 Мбит/с на зрителя, без ошибок; 10 зрителей MJPEG — 8.2 Мбит/с на зрителя.
- Проверки `scripts/check_demo.py`: `stream_sync` — рамка движущегося человека при ответе детектора через 1 с, `blur_new_person` — голова размыта на первом кадре с новым человеком.

```bash
python scripts/load_test.py --base http://127.0.0.1:8000 --camera demo_reel --viewers 50 --seconds 60 --mode hls --pid <PID>
python scripts/load_test.py --camera demo_reel --mode mix --viewers 40 --monitor 10 --seconds 60
```

## Известные ограничения

- Трансляции зависят от доступности источника; ссылки YouTube и Ivideon живут ограниченное время и обновляются автоматически.
- Плитки дороги: на Mac с плитками на 4 трансляциях `live_*` около 0.56 кадра/с (раздел «Обработчики и плитки»); на сервере обработчики и потоки ONNX подбираются заново.
- На `live_3` детектор принимает деревянные щиты за `bus` и `truck`: рядом работающие люди дают тревоги `proximity`.
- Бег прямо на камеру без калибровки камеры не отличается от шага вблизи: рост рамки при шаге рядом с камерой совпадает с бегом вдалеке. На контрольном наборе бег к камере (`running_04.mov`) не находится.
- Бег со смазанным силуэтом не находится: детектор теряет человека в фазе бега (`running_03.mov`).
- `proximity`: человек, стоящий у припаркованной техники, даёт тревогу, движение техники не учитывается. Зона тревоги — 2 роста человека от бокса техники.
- Живые тревоги работают на `onnx`: через облачный сервис LinQ кадр идёт 5–10 с (`reports/benchmarks.json`).
- API без авторизации, CORS открыт для любого источника (требование `CONTRACT.md`, раздел 6). Сервер по умолчанию слушает только `127.0.0.1`.
