# ML и LinQ: материалы для слайдов

## 1. Модели

| Модель | Объекты | Вход |
|---|---|---|
| `yolov8n-pose` | `person`, 17 ключевых точек | 640×640 |
| `yolov8n` | `car`, `truck`, `bus`; погрузчик — `truck`, 38 кадров из 50 | 640×640 |

## 2. TPU и CPU

| Этап | Где |
|---|---|
| Препроцессинг: letterbox 640 | CPU |
| Свёрточная часть pose и det, int8 | LinQ TPU |
| Декодирование DFL, сборка выхода | CPU, ONNX Runtime |
| NMS, перевод координат | CPU |

Граф разрезан: при квантовании полного графа обнулялись уверенности ключевых точек. Точность `linq` против `onnx` на 20 кадрах: IoU пар 0.95.

## Люди на общем плане (ML-16)

- Люди на общем плане реального цеха: 116 из 193 вместо 7 из 193, плитки включаются для камер общего плана.

## 3. Замеры

| Конфигурация | Кадров/с | Время на кадр |
|---|---|---|
| `onnx`, CPU Apple M4, 1–8 потоков | 8.07–8.74 | 114.5–123.9 мс |
| `linq` через сервис, 8 процессов ретранслятора, 8–16 потоков | 0.80 | 1.24 с |
| `linq`, только время ускорителя, pose + det | 10.98 | 91.1 мс |

- Время на кадр = 1000 / fps при параллельной обработке. Задержка одного кадра через сервис: 5–10 с.
- Через сервис: 0.80 кадра/с при 8 процессах ретранслятора, было 0.26 при 1 процессе.

## 4. Потоков на плату

1 поток по 10 кадров/с на одну плату LinQ по времени ускорителя: 91.1 мс на кадр, pose + det.

## Детекция в беге (ML-12)

| Видео `dev/` | Доля кадров с человеком при `conf` 0.4 / 0.25 / 0.15 / 0.1 | Уверенность |
|---|---|---|
| `running.mov` | 1.00 / 1.00 / 1.00 / 1.00 | 0.85 |
| `running_02.mov` | 1.00 / 1.00 / 1.00 / 1.00 | 0.80 |

- На видео настройки смаза в беге нет, снижение порога до 0.1 события не меняет. Порог оставлен 0.4.
- Правило `running` распознаёт бег: на `running.mov` тревога через 4,3 с, на контрольном `running_07.mov` через 1,3 с. Развитие: калибровка камеры по полу, съёмка 25–30 кадров/с для подсчёта частоты шагов. Подробно: `backend/README.md`, раздел «Подбор порогов».

## 6. Метрики

Пороги подобраны на `dev/`, метрики посчитаны на независимых дублях.

| Тип | tp | fp | fn | Видео |
|---|---|---|---|---|
| `fall` | 1 | 0 | 0 | `fall_02.mov` |
| `running` | 1 | 1 | 4 | `running_03.mov`…`running_07.mov` |
| `danger_zone` | 1 | 0 | 0 | `danger_zone_02.mov` |
| `proximity` | 3 | 3 | 0 | `running_05.mov`…`running_07.mov` |

- Тревога о падении через 3.3 с после начала падения, из них 1.5 с — ожидание неподвижности.
- Тревога о входе в опасную зону через 1.6 с.
- Бег: на новом видео тревога через 1,3 с.
- Сцена без нарушений, 7 с, правила `fall`, `running`, `proximity`: 0 тревог.
- Правило `running` распознаёт бег: на `running.mov` тревога через 4,3 с, на контрольном `running_07.mov` через 1,3 с. Развитие: калибровка камеры по полу, съёмка 25–30 кадров/с для подсчёта частоты шагов. Подробно: `backend/README.md`, раздел «Подбор порогов».
- Сближение с техникой: на контрольных видео найдено на 3 из 3, тревога через 2,5–6,3 с.
